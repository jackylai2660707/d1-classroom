# D1 學生工坊 2.0：初始化與實機驗收

學生只做：掃描機器狗 → 核對標籤上的完整 Wi-Fi MAC → 點連線。沒有 UID、配對碼、ID 表或學生端課室設定。以下工作由技術人員做一次。

## 部署前核對

- 此橋接使用 zsl-1 的 mc_sdk_zsl_1_py.HighLevel；先確認實體型號、韌體及原廠允許的機載 SDK 部署方式。帶輪等其他型號不可直接套用。
- 初始化包已包含原廠 SDK V2.0.7 完整原包、SHA-256 與 BSD 3-Clause 授權；腳本自動選擇 aarch64／x86_64，並自動尋找機身 CPython 3.10。學生 Windows 不安裝此 SDK。
- 第一隻實機先依原廠指南確認機內 SDK 通訊配置與硬體停止方式；後續同型號／同韌體狗使用相同操作。初始化腳本能檢查 Python、網卡、SDK 匯入及連線，無法自動判定所有韌體型號相容性。
- 路由器 DHCP 即可；電腦與狗需在同一個可互通、允許廣播的 IPv4 網段，關閉用戶端隔離。允許 UDP 8765 掃描、TCP 8765 控制、TCP 8554 RTSP。無需固定 IP，不對外轉發這些埠。
- 機身 Wi-Fi 需使用穩定 MAC，不啟用隨機 MAC；標籤與掃描畫面使用相同網卡。更換網卡後須更新標籤。

## 同一份腳本逐台執行

1. 讓狗加入課室 Wi-Fi，從路由器取得這次 SSH 地址。部署時機身保持靜止。
2. 從完整交付包上傳「技術人員部署/d1-setup.zip」，或使用單獨的「D1機器狗初始化包.zip」，遠端都命名為 d1-setup.zip。
3. 在 Windows 解壓完整交付包的資料夾開啟 PowerShell，將下面的機器狗IP替換成實際地址：

```powershell
scp ".\技術人員部署\d1-setup.zip" firefly@機器狗IP:~/d1-setup.zip
ssh firefly@機器狗IP
```

4. 在機器狗終端執行：

```sh
unzip -o ~/d1-setup.zip -d ~/
cd ~/d1-setup
sudo bash install.sh
```

不需另下載 SDK，也不需輸入 SDK 路徑。相同機型與韌體的狗使用相同命令。登入帳戶若不同，依原廠提供的帳戶替換 firefly。

腳本依序檢查機身 CPython 3.10、Wi-Fi 網卡、DHCP 地址與 CPU 架構；驗證原廠 ZIP 的 SHA-256，解出對應的兩個 SDK 模組及授權，確認可匯入後安裝至 /opt/d1-classroom/sdk。完整原廠 ZIP、雜湊資料與授權另外保存在 /opt/d1-classroom/vendor。服務使用這些固定路徑，不依賴上傳資料夾。

之後安裝橋接與 systemd，檢查 HTTP 與 SDK；只有通過才輸出「初始化成功」、完整 Wi-Fi MAC 和開機自啟狀態。標籤保存於 /opt/d1-classroom/機身標籤.txt。SDK 就緒檢查未通過時停用橋接服務，修正後重跑同一命令。

初始化包內容：

```text
d1-setup/
  install.sh、install.py、bridge.py
  README.md、README.txt、LICENSE
  sdk/
    agibot_D1_Edu-Ultra_V2.0.7.zip
    manifest.json
    LICENSE.vendor.txt、README.vendor.md
```

腳本自動優先使用 python3.10；未安裝時清楚報錯，不擅自更換機身作業系統。隨包 SDK 需要 Linux CPython 3.10 及相容的原廠運行環境；完整交付不代表能在不相容的系統上載入二進位模組。

重複執行保存已選的網卡與 SDK 通訊地址，並保留一份 .previous 備份；相同 SDK 不重複改寫。兩張 Wi-Fi 網卡時用 --interface 指定；服務預設使用 sudo 的原登入帳戶，也可用 --user 指定。--sdk-dir 只保留給技術人員特殊覆寫，正常部署不使用。

## SDK 機內地址

橋接與運動控制器都在狗上，預設以 127.0.0.1 初始化 SDK。原廠互動 Python 範例使用此地址，但機身 sdk_config.yaml、運動服務及實際韌體必須配合；不能假設所有出廠映像都已配置好。

若已驗證的機內地址不同，技術人員可用 --sdk-address 指定同一個機內地址；若韌體要求綁定狗的 Wi-Fi 當前 IP，可用：

```sh
sudo bash install.sh --sdk-address auto
```

auto 會動態讀取所選 Wi-Fi 網卡；偵測到地址改變後先停止、退出，由 systemd 重啟並重新初始化 SDK。原廠服務內的 target_ip／SDK_CLIENT_IP 如仍寫死舊 IP，仍須按該韌體指南處理。腳本不會猜測或改寫原廠運動配置，避免把未驗證設定寫入機身。

SDK 初始化卡住、匯入失敗或就緒檢查未通過時，查看：

```sh
journalctl -u d1-classroom -n 50 --no-pager
systemctl status d1-classroom
```

完成初始化只代表軟體連線正常，不代表已測得物理停止。SDK 機載負載及原廠是否允許此部署仍需核對。

## 學生端與連線行為

開完整 Windows 工具，保持練習模式。點掃描，核對機身完整 MAC，選自己的狗連線。開放的同網設備可申請空閒狗的控制權；MAC 用於辨識，並非秘密密碼。控制憑證只存記憶體，一隻狗同時一台電腦，不能強制搶占。

橋接每 50 ms 監看動作期限；心跳約 350 ms，超過 1.2 秒未收到則嘗試零速度並釋放控制權。單次平移最多 3 秒、速度 .05–.2 m/s、轉向 .3 rad/s、角度 1–45 度、程序最多 60 秒，電量低於 30% 不開始。轉角為時間估算，非閉環定位。

程式、AI 和相機解碼在 Windows 執行，運行中需保持連線；不是上傳後離線運行。機器狗相機使用本次連線地址的 rtsp://IP:8554/test。

## 現場驗收順序

1. 一台電腦、一隻狗：正常掃描、MAC 標籤一致、電量、連線及斷開。
2. 關閉／重開工具、還原電腦、換 DHCP 地址／網路後，重新掃描能連線；不續跑舊程式。
3. 第二台電腦搶連同一隻狗必須拒絕；原連線停止及釋放後才能接手。
4. 站立、零速度、趴下；低速前進 0.5 秒及左右 15 度，記錄實際延遲、距離與機身狀態。
5. 運動中點停止、斷 Windows 網路、關閉工具、結束橋接及模擬 SDK 錯誤，依現場已驗證的硬體停止方式處理並記錄。軟體零速度回覆不代表物理已停；程序被殺或控制器故障可能使軟體停止無效。
6. RTSP、分類持續運行與多組負載，最後才擴大到 10 台 PC／10 隻狗，並完成教師培訓及試教。

使用交付包的「列印資料/操作與試教記錄.pdf」填寫每台狗 MAC、韌體、時間、觀察者與結果。未完成實機驗收前維持練習模式。
