# 測試指南

2.0 先從 output/D1彩色課程套件/使用說明.html 開始。離線教程與 Windows 工具是兩個入口，互相連結；課件頁面不直接控制狗。

## 新版教程檢查

在 d1-classroom 執行 node tests/courseware-smoke.cjs --packaged。此命令需要 Playwright 與 Microsoft Edge；D1_PLAYWRIGHT 可指向已安裝的模組。它使用 file URL，驗證 21 頁、16 課的 4 個章節、1440 / 390 / 320 寬度、所有本地連結、零外部請求、記錄匯出匯入、錯課拒絕、圖片放大、投影模式與成品教程按鈕。

人工可選第 3 課，填寫「修改與測試」，到「回顧與保存」匯出記錄，再重開頁面並匯入。第 13 課應有 15 行 v1 / v2 比較；第 12 課明確提示外部訓練網站需要網路。

列印資料共有 16 / 18 / 5 頁。生成後以 Poppler 渲染所有頁面，檢查字型、表格、頁界與可書寫空間。證據在 build/qa/courseware/。

本專案有三層測試：Windows 成品練習、程式核心與假 SDK、現場實機。先完成前兩層，再依部署文件進行實機驗收。

## 1. 先測 output 成品（不需要機器狗）

1. 雙擊根目錄 `啟動學生工坊.cmd`；也可直接開啟 `output/D1彩色課程套件/學生工具/D1學生工坊/D1學生工坊.exe`。保留 EXE 相鄰檔案與 resources。
2. 確認「練習模式」勾選。無機器狗時不必掃描或連線。
3. 課程範例選第 3 課，點「載入」→「運行」。預期記錄列出動作，最後出現「程序完成」，沒有「程式錯誤」。此模式顯示指令記錄，沒有物理運動模擬。
4. 點「保存專案」，存至自己的作品資料夾；改載其他課，再用「開啟專案」載回。確認課程、積木及 Python 內容恢復。
5. 切到 Python，輸入以下程式並運行；看到站立、等待、停止與完成記錄即通過。

```python
dog.stand()
dog.wait(seconds=1)
dog.stop()
```

6. 在練習模式運行 `while True: pass`，按「停止」，確認可取消且運行按鈕恢復。再輸入缺少冒號的 `for i in range(2)`，確認顯示程式錯誤且介面仍可操作。
7. 點「匯入 TensorFlow.js ZIP」，選 `output/D1彩色課程套件/配套檔案/備用色卡模型.zip`。預期顯示「已載入」。
8. 點「開啟測試圖片」，選配套檔案的 `色卡示例圖片/左轉卡/示例_4.png`，確認顯示分類名稱及百分比。這只驗證匯入與推論流程，不能代表真實場景準確率。
9. 點「電腦相機」，允許相機權限，觀察畫面和即時分數，完成後點「關閉」。靜態圖片不會提供連續三張新畫面的事件。

每項記錄通過／失敗、Windows 版本及錯誤文字。第 11–15 課需要相機或模型，不能直接把沒有模型時的等待當成通過。

## 2. 核心自動測試

需要 Node.js 22+、Python 3；核心測試使用標準庫，不需要 npm 依賴，也不會連接實體機器狗。在專案根目錄 PowerShell 執行：

```powershell
powershell -NoProfile -File scripts/test.ps1
```

若 Python 不在 PATH，可指定：

```powershell
powershell -NoProfile -File scripts/test.ps1 -Python 'C:\你的Python路徑\python.exe'
```

預期所有核心測試通過；Windows 會跳過 Linux shell 測試 1 項。JavaScript 包含真實 UDP／HTTP 假橋接整合測試、擴充指令參數限制和持續辨識；Python 包含初始化腳本、SDK 原包兩種架構與授權、雜湊／ABI 失敗拒絕、重複安裝、AP 網段、心跳鎖分離、高風險允許與特殊動作退出檢查。涵蓋速度與時間限制、影像確認去重、完整 Wi-Fi MAC 核對、控制權占用、心跳中斷、低電量、停止和程序期限。當次新增功能與測試結果見「學生工坊擴充指令」紀錄，不把假 SDK 通過當成新動作實機驗收。

可在 `d1-classroom` 分別執行 `node --test tests/core.test.cjs` 和 `python -m unittest discover -s tests -p '*_test.py'`。

另有成品自動測試 `tests/packaged-smoke.cjs`，需可解析的 Playwright 套件（或以 `D1_PLAYWRIGHT` 指定其模組目錄），執行：

```powershell
cd d1-classroom
node tests/packaged-smoke.cjs
```

它啟動 output 內的 EXE，使用獨立暫存資料測第 1–14、16 課練習、第 15 課合成即時影像確認與超時、模型匯入及圖片分類；不使用實體狗或相機。既有 `build/check-*.cjs` 部分會重寫教材圖片與課程專案，且含作者環境絕對路徑，請勿將它們視為一般測試入口。

## 3. 修改原始碼後測試

在 `d1-classroom` 執行：

```powershell
pnpm install
pnpm run bundle
pnpm test
python -m unittest discover -s tests -p '*_test.py'
pnpm start
```

確認開發版正常後執行 `pnpm run package` 更新 output 應用，再重做成品測試。此命令只更新解壓資料夾中的應用；外層交付 ZIP、原始碼 ZIP 及雜湊清單用 `python build/deliver.py` 重新發佈。教程用標準庫生成；PDF 需要 requirements-author.txt 的 ReportLab 與中文字型，詳見原始碼 README。

## 4. 實機驗收

新版不使用 robots.json 或 D1-001。先在每隻狗執行同一份 install.sh 初始化，貼 Wi-Fi MAC 標籤；學生每次開課點掃描、核對 MAC、點連線。

依 `d1-classroom/技術部署與實機驗收.md` 完成對應韌體／SDK、DHCP／Wi-Fi MAC、Linux 橋接與現場停止手段驗收，再依序測：身分與電量 → 站立及趴下 → 低速短動作 → 停止與斷線 → RTSP／模型 → 多機負載。逐台記錄實際延遲、停止距離和觀察者。

軟體假 SDK 通過不能代替實機通過；本次整理沒有執行機器狗動作。現場證據填入 output 的「列印資料/操作與試教記錄.pdf」。

## 新版完整 Windows 流程

需要 Playwright 模組可用；或用 D1_PLAYWRIGHT 指向現有模組目錄。在 d1-classroom 執行 `node tests/app-smoke.cjs --packaged`。測試啟動獨立使用者資料與本機假 SDK，真實 UDP 收發限定回環地址，驗證掃描、連線、占用、假動作、橋接中斷與重啟還原後連線。它不會尋找並控制實體狗。


完整 ZIP 發佈後執行 python tests/delivery-audit.py，逐項核對 SHA-256、ZIP 成員、初始化原包與來源完整性。2.0 已另做原始碼獨立目錄重建、完整 ZIP 搬移解壓後的成品啟動與教程導覽。


## 公司接手與私人 Release

完整流程見「公司電腦實機測試.md」。公司檢查命令為 scripts/preflight.ps1；下載腳本按 releases/v2.0.0.json 校驗，先完成所有 SHA-256 核對才解壓。

作者環境可用 python scripts/test_handoff.py 驗證乾淨目錄還原、既有資料保留、取代時備份、參考資料及壞檔拒絕；此測試需要 output/github-release/ 內已準備好的三個 ZIP，不會連接真狗。

推送前用 python scripts/check_repository.py 檢查已暫存檔案。GitHub Actions 跑 Linux 核心與安裝器測試；GUI、硬體與整班網路仍由本機 / 現場測試。
