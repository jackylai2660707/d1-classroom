# 輸入 IP 初始化新機器狗

## 從 Release 下載後，先照這裡做

沒有 Python／PuTTY 或需要離線跨電腦使用時，改用新建的獨立 Portable 包。整包解壓後雙擊「初始化新機器狗.cmd」，無需安裝工具或上網；包內 runtime 固定為 Windows x64。使用步驟見 [Portable 說明](Portable初始化說明.txt)。既有已發布 v2.1.0 附件不包含此 portable runtime，不能把舊包當作已更新。

如果想在 Windows「只輸入 IP」，下載 **D1-Classroom-2.1.0-Windows-x64.zip**，右鍵「全部解壓縮」，進入 **D1彩色課程套件 → 技術人員部署 → 一鍵初始化**，雙擊「初始化新機器狗.cmd」，輸入 IP 按 Enter。PC 需 Python 3、OpenSSH 和 PuTTY Plink；預設帳號密碼由工具處理。等待明確成功與完整 MAC，再去學生工坊掃描連線。

**D1-Robot-Setup-2.1.0.zip／d1-setup.zip 是狗端 Linux 包，不是 Windows 一鍵工具。** 只下載這個 ZIP 時，見原始碼 `d1-classroom/bridge/README.setup.txt` 的「手動流程」：先在 Windows 用 scp 上傳，再 SSH，在狗端執行 provision.py --probe 和 sudo python3.10 provision.py --apply。不要直接雙擊 install.sh，亦不要把裸 install.sh 的舊流程當成新狗完整初始化。

在倉庫根目錄雙擊「初始化新機器狗.cmd」，輸入狗當前的局域網 IPv4。程式使用 firefly 帳號及原廠預設登入資料；不需要另找 SDK。PC 需有 Python 3、Windows OpenSSH 的 ssh-keyscan，以及支援 -pwfile 的 PuTTY Plink（目前開發電腦已備妥）。程式不會自動下載依賴。

## 使用前

先讓狗趴穩、保持靜止、停止學生程式並斷開所有控制端。現場人員應知道原廠硬體停止方式。初始化會啟動 SDK，可能使原廠 App／手柄無法同時控制；必要時會單獨重啟原廠運控。初始化不會測站立、趴下、握手、跳躍等動作，但 SDK 啟停與運控重啟仍會影響控制狀態。

PC 和狗在同一可互通局域網即可，不需網際網路；狗的 AP 可作為傳輸網路。腳本並非固定 IP 設定器，不會改 Wi-Fi、DHCP、AP、防火牆或作業系統。

## 指令入口

```powershell
# 互動輸入 IP，完成檢查後初始化
python scripts/initialize-robot.py

# 直接指定當次 IP
python scripts/initialize-robot.py 192.168.5.23

# 只讀機身檢查：不上傳、不安裝、不初始化 SDK
python scripts/initialize-robot.py --check-only 192.168.5.23

# 本機建立並核對初始化包：完全不連機器狗
python scripts/initialize-robot.py --prepare-only
```

雙擊入口會停留畫面以便查看結果。預設使用原廠共同密碼；不同密碼可在當次程序以 D1_SSH_PASSWORD 環境變數覆寫，不提供明文命令列密碼參數。

## 自動完成的工作

1. 只接受 RFC1918 私有 IPv4，讀取 SSH ED25519 指紋，並釘選到當次連線。第一次是信任首次使用（TOFU），不能代替現場核對設備。成功讀出穩定 Wi-Fi MAC 後，把指紋按 MAC 保存於忽略的 field-results/initialization/；同 MAC 的金鑰變更拒絕繼續，不會自動覆寫。
2. 只讀核對 Ubuntu 22.04、ARM64、CPython 3.10、wlan0 MAC、當前 wlan0／ap0 地址、原廠服務、空間及運控配置。只自動處理本次現場已驗證的 XG、運控 0.5.1-xg，以及完全符合既有已驗證 SHA-256 的原廠運控啟動腳本。其他型號／韌體停止處理，不猜參數、不升級韌體。
3. 從目前原始碼建立含完整原廠 SDK、授權、manifest、bridge.py、highlevel.py、install.sh、install.py、provision.py 的同一初始化包，核對 SDK 雜湊和 ZIP 內容。每台狗使用相同腳本，IP 只決定傳輸目的地。
4. 若既有橋接 active，僅以探索協議確認 available；busy 或無法確認時拒絕更新，不搶控制權。
5. 上傳到唯一暫存目錄，核對 SHA-256、拒絕 ZIP 路徑穿越，再解壓。密碼僅短暫寫入限制目前使用者及 SYSTEM 可讀的本機檔案供 Plink 使用，結束／例外後清除；sudo 密碼經標準輸入提供，子程序不繼承密碼輸入。終端輸出及記錄不保存密碼。強制結束整個 PC 程序時可能來不及清除，請檢查 local/robot-init/ 的 ssh-*.tmp；此目錄被 Git 忽略。
6. 匯入／檢查 SDK 類別方法，但不建立機器狗實例；然後備份舊橋接、設定與權限到機身 /var/lib/d1-classroom-init/唯一時間目錄，建立 180 秒未提交自動還原 timer。
7. 先經同一份 install.sh --no-start 安裝。對已驗證配置才將 SDK 回傳及綁定地址改為 127.0.0.1，必要時只重啟 motion_control，不重啟整台狗。保留 ROBOT_TYPE，不改原廠 robot-launch.service。只有 AP 有 IPv4 時仍可安裝，身分使用 wlan0 的固定 MAC。
8. 啟動橋接並驗證 sdk_ready 與 MAC；成功後取消 timer，列出 MAC、備份及還原命令。新狗預設不設開機自啟；既有狗保留原有啟用狀態。不自動重開機。

## 失敗與還原

初始化失敗時嘗試停用新橋接、恢復原廠兩份設定與舊橋接、必要時重啟運控，恢復原本服務狀態。失敗的新橋接移到備份目錄保留，沒有遞迴刪除機身目錄。斷線時若安裝程序仍能執行，會捕捉中斷並嘗試還原；未提交 timer 也會執行保護性還原。這不是停電、磁碟故障或 SDK 卡死下的絕對保證。

若 PC 顯示逾時，保持狗開機至少 3 分鐘，檢查 field-results/initialization/ 的結果；不能當作成功。不要盲目連續重跑。成功結果 JSON 包含對應備份的 rollback_command，可在狗靜止、硬體停止方案可用時由技術人員 SSH 執行。還原也會停止橋接和可能重啟運控，應現場監看。

## 成功後

到最新版學生工坊掃描，核對列出的完整 MAC，再逐項完成連線、停止、相機及單台動作驗收。初始化成功只表示軟體／SDK 就緒，不等同可直接授課。重開機後若未設自啟，需要手動啟動橋接；本工具不順帶更改這項政策。

本工具也隨本機 2.1.0 套件附在「技術人員部署/一鍵初始化/」，該目錄已包含完整 bridge/sdk 與腳本，搬到另一電腦時須保留整個目錄，不能只複製 CMD。2.1.0 未重寫已發佈 v2.0.0 Release 或既有 manifest。

## 本次驗證

新增單元測試涵蓋私有 IP／命令注入拒絕、SSH 指紋和變更拒絕、密碼暫存檔清除、ZIP 路徑穿越拒絕、只讀模式不執行 sudo／上傳、已驗證設定最小修改、正常安裝不新增自啟、失敗還原原廠及舊橋接、未知版本／使用中拒絕。另在 Windows 實測 Plink -pwfile 支援、密碼檔 ACL 和清除。只建立本機初始化包，未連線任何新狗；完整首次實機初始化仍待狗開機後執行。
