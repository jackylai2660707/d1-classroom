# 跨電腦繼續開發

這個私人倉庫包含可修改的原始碼、鎖定的依賴清單、原廠 SDK、教材素材與建置腳本。開發版可以直接連線機器狗，不需要先打包 EXE。Release `v2.0.0` 是固定的交付基準；公司電腦開發時運行目前 checkout 的程式。

## 第一次設定開發電腦

可使用 Windows 10 / 11 x64，或 Windows 11 ARM64 開發；ARM 電腦另見下節的 x64 交付要求。先安裝 Git、GitHub CLI、Node.js 22+ 與 Python 3.10+。狗上的原廠二進位 SDK 要求 **Linux CPython 3.10**，這與電腦端 Python 版本是兩件事。

```powershell
gh auth login
gh auth setup-git
gh repo clone jackylai2660707/d1-classroom
cd d1-classroom
git config user.name "你的 Git 作者名稱"
git config user.email "你的 Git 提交電郵"
npm install --global pnpm@11.0.9
powershell -NoProfile -File scripts/setup-dev.ps1
powershell -NoProfile -File scripts/test.ps1
cd d1-classroom
pnpm run dev
```

`setup-dev.ps1` 使用 package.json 指定的 pnpm 11.0.9，按 pnpm-lock.yaml 安裝，並產生被 Git 忽略的 renderer bundle、Skulpt、Blockly media 與離線教程。不必搬另一台電腦的 node_modules，也不依賴作者電腦的 Codex runtime。若沒有同版本 pnpm，腳本使用 npx 呼叫指定版本；之後也可用 `npx --yes pnpm@11.0.9 run dev` 啟動。

倉庫根目錄有 scripts/、docs/、README.md；裡面那層 d1-classroom/ 才是 Node / Electron 應用。Git 命令建議回到倉庫根目錄執行。

首次安裝需能連到 npm 與 Electron / FFmpeg 的下載來源。若公司代理或下載策略攔截，先由 IT 放行或配置 npm / pnpm 的代理；不要因下載失敗修改 lockfile、移除完整性校驗或把公司的代理密碼提交到 Git。

## Windows ARM 開發與 x64 交付

本臺電腦已備妥獨立 x64 工具與 `scripts/dev-local.cmd` 啟動入口，實際使用見 [ARM 開發機現場準備](ARM開發機現場準備.md)；使用此入口可避免終端誤用系統 ARM Node.js。

本專案允許在 Windows 11 ARM64 電腦繼續開發，正式 Windows 學生工坊仍統一交付 **x64**，供一般 Intel / AMD 64 位元 Windows 使用。日常口語的「x86 電腦」在這裡指這類電腦；真正的 32 位元 x86 Windows 不在目前支援範圍。

- HTML、CSS、JavaScript、課程 JSON 與 PDF 內容不因開發電腦是 ARM64 而變成 ARM 專用。Windows 控制端透過網路連狗，不需要安裝 D1 專用硬體驅動。
- 學生工坊包含 Electron 與 FFmpeg 執行檔，這兩項正式交付都必須選 Windows x64。Windows 11 ARM 可透過相容執行運行 x64 軟體，但這不會把 ARM64 成品轉成 x64。
- 目前 setup-dev.ps1 未指定目標架構；package.cjs 直接複製 node_modules 中的 Electron 與 FFmpeg，沒有自動轉換或拒絕 ARM64。不能把「在本機打包成功」當作輸出一定是 x64。
- ARM 電腦準備開發 / 打包環境時，優先使用 Windows x64 Node.js 搭配鎖定版本 pnpm，讓 Electron 與 FFmpeg 安裝流程使用 x64；先以 `node -p "process.arch"` 確認該終端輸出為 `x64`，再執行 setup-dev.ps1。切換 Node 架構時須重新安裝應用依賴，不沿用 ARM64 的 node_modules。若保留 ARM64 Node.js，則需另外明確設定 Electron 與 FFmpeg 的 x64 安裝目標，不能直接依賴預設安裝。
- 後續修改建置腳本時保留 x64 交付目標，不因開發主機架構改成交付 ARM64；狗端 SDK 按狗端 Linux 架構使用，不受 Windows 主機架構影響。

依使用者工作方式，不額外增加例行多架構驗證、反覆換機或完整相容性測試流程；按實際修改執行原有必要檢查。以上是開發與交付約定，本次僅補文檔，尚未修改安裝 / 打包腳本或完成成品相容性驗收；真機控制與停止仍按原有現場規範處理。

## 每天開始、修改與提交

```powershell
# 在倉庫根目錄；先處理自己尚未提交的改動，再更新
git status
git pull --ff-only
git switch -c feat/你的功能名稱

cd d1-classroom
pnpm install --frozen-lockfile
pnpm run dev
```

`pnpm run dev` 每次啟動都先 bundle。修改 renderer.js 後，關閉開發版再重跑此命令；HTML / CSS 也建議重啟以確認載入的是新檔。不要同時開著發佈版 EXE 和開發版去連同一隻狗。根目錄「啟動學生工坊.cmd」啟動的是 output 成品，並不會自動採用原始碼改動。

完成一項可驗證改動後：

```powershell
# 回到倉庫根目錄
cd ..
powershell -NoProfile -File scripts/test.ps1
git diff --check
git status
git add d1-classroom/app/renderer.js d1-classroom/app/style.css
# 依實際改動加入其他原始碼、測試和文檔
python scripts/check_repository.py
git diff --cached
git commit -m "Describe the completed change"
git push -u origin HEAD
```

上面兩個 git add 路徑只是修改 UI 的例子；新測試和文檔也要一起加入。之後在同一分支繼續提交用 `git push`。公司功能分支可用 `gh pr create --base main` 請求合併，或依個人工作方式合併回 main；不要 force push 去覆蓋另一台電腦的改動。切回原電腦時，checkout 同一分支再 `git pull --ff-only`。

## 改什麼，從哪裡開始

| 要改的內容 | 原始碼入口 | 修改後 |
|---|---|---|
| Windows 工具 UI / 按鈕 | app/index.html、style.css、renderer.js | 重啟 `pnpm run dev` |
| 積木與 Python 產生 | app/renderer.js、python-worker.js | bundle、練習程式與錯誤處理測試 |
| 掃描、連線、RTSP / IPC | app/discovery.cjs、main.cjs、preload.cjs | 核心、假 SDK、開發版實機測試 |
| 動作與限制 | app/policy.cjs、bridge/bridge.py | 同時核對兩端限制；更新橋接後重做相關現場測試 |
| AI 模型與事件 | app/tm-preprocess.js、vision-core.cjs、renderer.js | 新圖片、即時確認與超時測試 |
| 教程內容與範例 | curriculum/lessons.json | `pnpm run curriculum`、bundle、生成教程 / 工作紙 |
| 教程外觀與記錄互動 | courseware/style.css、course.js | `python build/courseware.py`，再重開教程 |
| 機身初始化 / 自啟 | bridge/install.sh、install.py | 安裝器測試、相容真機重新安裝驗收 |

表中 app/ 等路徑均相對於應用 d1-classroom/。不要編輯 renderer.bundle.js、output HTML 或解壓後 ASAR 當作原始碼。

## 在另一個網路做實機 debug

先按 [公司電腦實機測試](公司電腦實機測試.md) 初始化第一隻狗與核對現場停止方式；電腦、狗在同一可互通 IPv4 網段，DHCP 可用。開發版仍是「掃描 → 核對完整 Wi-Fi MAC → 連線」，沒有環境限定的 IP 表或首次配對。

從應用目錄啟動：

```powershell
pnpm run dev:debug
```

- renderer：視窗按 Ctrl+Shift+I，或從 View → Toggle Developer Tools 開啟 DevTools，看 Console / Sources。瀏覽器 DevTools 只看得到介面與 preload 暴露的 API。
- Electron 主程序：啟動終端保留主程序輸出；`dev:debug` 的 Node inspector 僅綁 127.0.0.1:9229，可由支援 Node attach 的 IDE 附加。
- 狗端服務：SSH 讀 `journalctl -u d1-classroom -f`。結束追蹤用 Ctrl+C，不代表停止機器狗。
- 動作與電量：先在練習模式核對程式，再按現場短動作順序測試；記錄 SDK / 韌體、MAC、commit、Release 基準及實際現象。

修改純 UI 不需要重裝狗端。修改 bridge.py、install.py 或 install.sh 後，使用尚未發佈的本地初始化包更新狗端，先確認機身停止，再重跑同一安裝流程。舊 Release 的初始化包不包含新改動。

Windows 控制程式、相機解碼與模型在電腦運行。暫停斷點、停止除錯器或重啟程式，可能中斷心跳；不要在機器狗運動時停在斷點上。需要逐步追蹤時先用假 SDK 或靜止設備；軟體取消仍需目視確認。

真機 robot.json、控制憑證、公司 IP、日誌與學生作品留在忽略的 field-results/ 或 local/。需要提交 bug 證據時，另外整理去識別的最小重現與測試。

## 不用真機先測修改

```powershell
# 倉庫根目錄；可選工具裝在 local/，不改應用依賴
powershell -NoProfile -File scripts/setup-dev.ps1 -WithUiTests
$env:D1_PLAYWRIGHT = (Resolve-Path local/test-tools/node_modules/playwright).Path
cd d1-classroom
node tests/app-smoke.cjs
```

不帶 `--packaged` 時，app-smoke 啟動當前原始碼的開發版與回環地址假 SDK，驗證練習、模型、MAC 掃描、占用與斷線取消。完整教程的下載連結 / 列印資料測試，需先按下節重建完整 output，再執行需要 Microsoft Edge 的 `node tests/courseware-smoke.cjs`；只做 setup-dev 的來源環境不含全部 PDF / ZIP，不能把缺交付檔案誤判為程式錯誤。真機動作、RTSP 與整班負載仍按現場表驗收。

## 從修改重建本地成品

一般 UI / 功能開發不需每次發佈 Release。要交付或在另一台機器測 EXE 時：

```powershell
# 倉庫根目錄；安裝可選 PDF 作者依賴，不會生成 PDF
powershell -NoProfile -File scripts/setup-dev.ps1 -WithPrintables
cd d1-classroom
pnpm run curriculum
pnpm run bundle
python build/courseware.py
..\local\venv\Scripts\python.exe build/printables.py
pnpm run package
python build/deliver.py
python tests/delivery-audit.py
```

PDF 修改 / 生成須依本倉庫 AGENTS.md 指定的 PDF 技能標記與渲染檢查；其他環境無該技能時也要逐頁渲染檢查，不能只看文字抽取。字型預設 Windows 微軟正黑體，可用 D1_FONT / D1_FONT_BOLD 指定。

本地 output、PDF 和 ZIP 都不會自動改 Git 或線上 Release。`deliver.py` 使用當前原始碼重建本地初始化包，所以更改橋接後可從這裡取包測試。若只做了 package，外層 ZIP 仍可能是舊的，需再 deliver。

## 發佈新版本

已發佈的 `v2.0.0` 與 releases/v2.0.0.json 保持不動。新成品先更新 package.json 版本，並同步教材版本顯示與驗收說明，例如 2.0.1；重建、測試後在倉庫根目錄執行：

```powershell
python scripts/prepare-release.py --version 2.0.1
```

腳本建立 releases/v2.0.1.json 與 output/github-release/v2.0.1/，已存在的版本清單會拒絕覆寫。一般修版只附新完整成品與初始化包；完整原廠 / 歷史參考資料仍可從 v2.0.0 取得。

先 commit 並 push 新清單與程式，再以新標籤建立私人 Release；具體命令見腳本產生的 release-notes.md。使用者選新版本時：

```powershell
powershell -NoProfile -File scripts/fetch-release.ps1 -Manifest releases/v2.0.1.json -Replace
```

提交程式不必等到發佈；公司可以持續以 Git 分支開發、連真機 debug、測試、commit 和 push。
