# 機器狗連線：最簡設計

日期：2026-10-20。狀態：1.1.1 軟體已實作並測試；實機初始化、SDK 效果與物理停止待現場驗收。

## 固定採用的方案

每隻狗使用同一份初始化腳本，Wi-Fi 採 DHCP，以機身 Wi-Fi 網卡的完整 MAC 辨識。學生每次上課重新掃描、選狗、連線，不依賴學校電腦保存任何設定。

不新增 UID、人工 ID、配對碼、登入、班級伺服器、IP 對照表或不同的連線模式。保留目前橋接的動作限制、心跳、停止和單一控制權機制。

## 老師只做一次

1. 將機器狗加入課室 Wi-Fi，SSH 登入。
2. 複製部署包，執行同一個 install.sh。
3. 腳本成功後，將輸出的完整 Wi-Fi MAC 印成標籤貼在狗身上。

腳本負責：檢查機型／SDK／Python → 安裝橋接 → 自動選定 Wi-Fi 網卡 → 設定並啟動 systemd → 檢查橋接與 SDK → 顯示成功及 MAC。

重複執行只更新／修復部署，不產生新的設備編號。找不到 Wi-Fi 網卡、選擇有歧義或 SDK 未就緒時，明確報錯，不顯示初始化成功。網卡名稱保存在狗端；所有狗使用相同腳本，學生端不需知道此名稱。

更換課室 Wi-Fi 時，只需讓狗與電腦加入新的網路，重新掃描；不用修改固定 IP。Wi-Fi 密碼本身仍需要在狗端設定。

## 學生每堂課做三步

**打開工具 → 掃描機器狗 → 對照標籤點連線。**

```text
[掃描機器狗]                         未連接

機器狗 · 4A:91   02:6D:3A:20:4A:91   可連線   [連線]
機器狗 · 7B:12   02:6D:3A:20:7B:12   可連線   [連線]
機器狗 · 8C:35   02:6D:3A:20:8C:35   使用中   [使用中]
```

- 完整 MAC 始終顯示；末四碼只用來方便辨認，不能當唯一識別。
- 日常只顯示可連線、使用中、準備中、已連接。使用中與準備中的狗不可點連線。
- 連線成功顯示 MAC、電量和斷開按鈕；不自動執行動作，保留現有練習模式開關。
- 掃不到時提示確認 Wi-Fi、機器狗電源與橋接服務，提供重新掃描。
- 電腦重啟還原後，按同樣三步操作即可，不需要匯入設定。

## 程式只分三部分

### 1. 初始化腳本：只負責安裝

install.sh 自動選擇機身 CPython 3.10 與 CPU 架構，檢查並安裝隨包原廠 SDK，再安裝 Python 橋接與 systemd 服務，選定用於識別的 Wi-Fi 網卡，並進行啟動檢查。它不分配 ID，也不產生學生端配置檔。

第一隻實機需先核對原廠 SDK 的機內通訊方式。其餘同型號、同韌體的狗使用同一部署包。SDK 的機內地址與課室 Wi-Fi 地址分開處理；優先使用原廠已驗證的穩定機內通訊地址，若 SDK 必須綁定 Wi-Fi IP，則由橋接讀取指定網卡的當前地址。此步必須在實機確認，不能僅憑工具能掃到狗就判定 SDK 可控制。

### 2. 機器狗橋接：回答掃描，執行指令

沿用 Python bridge.py，同一程序增加一個簡單的 UDP 回應執行緒；控制指令繼續使用現有 HTTP 協定。固定使用 **UDP 8765 掃描、TCP 8765 控制**，不需要新增第三方網路套件。

學生端廣播詢問，狗端單播回覆。示例：

```json
// 學生端詢問
{"type":"d1-discover-v1","request":"本次掃描的隨機值"}

// 機器狗回覆
{"type":"d1-robot-v1","request":"相同隨機值","mac":"02:6D:3A:20:4A:91","state":"available"}
```

IP 直接取回覆封包的來源地址，不另建 MAC／IP 配置表。橋接每次開機從指定 Wi-Fi 網卡讀 MAC，不另外生成設備 UID。狀態使用背景快取，不因掃描而調用運動指令或延長控制權。

### 3. 學生端：收集回覆，顯示列表

新增一個 discovery.cjs，使用 Node.js 內建 dgram。按掃描後，向作用中的可廣播 IPv4 介面送出詢問，約 3 秒內重送兩次並收集回覆；這是初始設定，需用課室網路驗證。

只接受本次 request、指定 type 與格式正確 MAC 的小型回覆；依完整 MAC 去重、排序。若同一 MAC 從不同 IP 回覆，顯示設備衝突，不任意選一台連線。掃描結束或取消時關閉 socket；重掃清掉舊 IP。

這取代原先的 ARP 掃描方案。ARP 只能提供網路鄰居快取，仍要額外探測與判斷哪些是狗；讓已安裝的橋接直接回覆 MAC，能省去逐 IP 掃描、快取更新、原生 ARP helper 與大網段遍歷。學生操作與 MAC 標籤完全相同。

掃描只收集設備，不取得控制權。Electron 主程序保存本次候選，介面點選時只傳候選索引，不接受任意 URL。名稱與 MAC 使用 textContent 顯示。

## 連線與停止保留最低必要機制

1. 點連線：向剛掃到的 IP 送出 /connect，帶 expected_mac。
2. 橋接核對自身 MAC、SDK 就緒狀態；在同一把鎖內判斷是否已被占用。
3. 空閒就發出本次連線的隨機控制憑證；後續心跳與指令必須帶這個憑證。學生不用看見或輸入它，只存在雙方記憶體。
4. 保留目前 350 ms 心跳、超過 1.2 秒未收到心跳則嘗試停止並釋放控制權的行為。這是軟體處理時限，實際停止效果須現場驗收。
5. 正常斷開時停止並釋放；電腦重啟、斷網或橋接重啟後，舊憑證不能再控制。重新連線後不自動續跑舊程式。

兩台電腦同時選同一隻狗，只能一台成功；另一台收到使用中提示。MAC 用來選狗，隨機控制憑證用來阻止其他連線混入指令，兩者用途不同。這個憑證不等於另一個設備 ID，也不是配對資料。

這是受控課室局域網的使用方式：同網設備都可申請連線空閒的狗，以標籤核對與老師現場管理分組。MAC 不作為秘密密碼。

## 環境前提

機器狗與電腦位於同一個可互通、允許局域網廣播的 IPv4 網段；設備隔離需關閉，防火牆允許 UDP／TCP 8765。受限校園網先由老師使用連線協助確認；第一版不增加跨 VLAN 中繼、雲端服務或多種自動回退機制。

## 最少驗收項目

- 同一部署包在兩隻同型號狗上執行，輸出不同的真實 Wi-Fi MAC，重跑安裝仍是相同 MAC。
- 清空學生端資料或重啟還原後，仍能掃描、點選、連線；全程不輸入設定。
- DHCP 換 IP、換課室網路後，重新掃描能找到相同 MAC，控制與相機使用新 IP。
- 兩台電腦搶同一隻狗只成功一台；過期指令不可影響新連線。
- 掃描／連線不產生動作；運動中停止、斷線、關閉程式及橋接故障均進行現場驗收。
