# 公司電腦接手與實機測試

倉庫：<https://github.com/jackylai2660707/d1-classroom>（Private）。交付版本 2.0.0，Release `v2.0.0`。本機與假 SDK 已驗證，真機項目需按下面流程現場完成。

要修改功能或介面、直接從原始碼連真機、debug、commit / push，先按 [跨電腦持續開發](跨電腦持續開發.md) 建立開發環境。本文的 Release 下載用來還原固定版本，不會載入你之後修改的原始碼。

## 1. 拉取與取得完整成品

建議 Windows 10 / 11 x64。只用成品需要 Git、GitHub CLI、Python 3.10+（執行檢查）及 Windows 內建 OpenSSH；修改原始碼另需 Node.js 22+、pnpm 11.0.9。登入能存取該私人倉庫的 GitHub 帳戶，不把存取權杖寫進命令或文件。

在 PowerShell 執行：

```powershell
gh auth login
gh repo clone jackylai2660707/d1-classroom
cd d1-classroom
powershell -NoProfile -File scripts/fetch-release.ps1
powershell -NoProfile -File scripts/preflight.ps1
```

Git 倉庫根目錄之下的 `d1-classroom/` 是應用原始碼，不是第二個 Git 倉庫。留在有 `scripts/` 和 `README.md` 的根目錄執行上面兩個腳本。

下載腳本會先核對版本清單內的大小與 SHA-256，再解壓成品到 `output/D1彩色課程套件/`，另放 `output/D1機器狗初始化包.zip`。不需要 Git LFS、不需安裝 SDK 到 Windows。既有成品會保留；要取代舊成品時加 `-Replace`，原資料先移到 `output/.previous-releases/`。

要一併取得原廠 PDF、STEP / URDF、研究摘錄與歷史教材：

```powershell
powershell -NoProfile -File scripts/fetch-release.ps1 -IncludeReferences
```

私人 Release 下載必須登入。若公司網路阻擋 GitHub，可以在能連線的電腦下載同一 Release 的三個 ZIP，帶到 `downloads/`，再執行相同腳本；已存在的 ZIP 會先核對，不重複下載。檔名和 SHA-256 見 `releases/v2.0.0.json`。只有測試目前套件時，參考資料 ZIP 可稍後下載。

## 2. 先做無機器狗測試

1. 開啟 `output/D1彩色課程套件/使用說明.html`，確認課程地圖與第 3 課能開啟。
2. 雙擊根目錄的 `啟動學生工坊.cmd`。程式缺檔時，重新解壓整套，不要只複製 EXE。
3. 保持「練習模式」，第 3 課 → 載入 → 運行，記錄應以「程序完成」結束。
4. 保存專案，切換課程，再重開專案。點「本課教程」應開啟對應課件。
5. 匯入 `配套檔案/備用色卡模型.zip`，開啟 `色卡示例圖片/左轉卡/示例_4.png`，確認有三類與分數。
6. 在教程填一筆記錄，匯出 JSON，重開頁面再匯入，確認內容恢復。

這一步不產生實體動作。練習記錄不模擬距離、姿態或碰撞。

## 3. 準備第一隻狗與網路

- 先確認是支援 zsl-1 `HighLevel` 的相容機型與韌體。不要把其他帶輪機型直接套用。
- 狗端需原廠相容的 Linux / CPython 3.10 環境。初始化腳本不替換作業系統，也不猜測原廠運動服務設定。
- 老師或技術人員先核對原廠硬體停止方式，劃好空場地與等待區，指定一位操作員守著停止；首輪只測一台電腦、一隻狗。
- 電腦與狗在同一個可互通、允許廣播的 IPv4 網段，路由器 DHCP 即可，不要求固定 IP。關閉 Wi-Fi 用戶端隔離；VPN、多網卡和公司訪客網路可能造成不互通。
- 所需通訊：UDP 8765 掃描、TCP 8765 控制、TCP 8554 RTSP；按公司網路政策由 IT 放行，不關閉整機防火牆。
- 狗的 Wi-Fi 使用穩定 MAC，不開隨機 MAC；標籤和掃描需對應同一張網卡。

部署時的 SSH 地址是狗當下 DHCP IP，只用於技術人員登入，不是學生連線設定。SSH 帳戶按原廠提供的值；下面使用 `firefly`。

## 4. 初始化一次，重開機驗證自啟

目前原始碼的一鍵初始化入口見 [輸入 IP 初始化](一鍵初始化機器狗.md)，使用已驗證韌體白名單、備份和回復。下方固定 Release 舊流程不包含這些新增修正；一鍵入口預設不新增開機自啟，不要混用兩種流程判斷當前部署狀態。

在 Git 倉庫根目錄的 PowerShell，把地址替換成路由器或原廠網路工具查到的真實值：

```powershell
$RobotAddress = '機器狗這次的IP'
scp ".\output\D1機器狗初始化包.zip" "firefly@${RobotAddress}:~/d1-setup.zip"
ssh "firefly@$RobotAddress"
```

在狗端執行：

```sh
unzip -o ~/d1-setup.zip -d ~/
cd ~/d1-setup
sudo bash install.sh
systemctl is-enabled d1-classroom
systemctl is-active d1-classroom
cat /opt/d1-classroom/機身標籤.txt
```

只有輸出初始化成功、服務 active、SDK 就緒，才繼續。記下輸出的完整 Wi-Fi MAC，貼在狗身，再在保持靜止的狀態重開機；重開後重新 SSH，重做兩個 systemctl 檢查，確認服務開機自啟。

原廠 SDK 原包、雜湊與授權已在初始化包裡，無需另備。SDK 預設機內地址為 `127.0.0.1`；若韌體需要其他地址，按 [技術部署與實機驗收](../d1-classroom/技術部署與實機驗收.md) 核對後再用 `--sdk-address`。不要為排錯隨意修改原廠 `sdk_config.yaml`。

失敗時保存以下輸出到本機測試記錄，不直接上傳機身設定：

```sh
python3.10 --version
uname -m
ip -4 addr
systemctl status d1-classroom --no-pager
journalctl -u d1-classroom -n 100 --no-pager
```

安裝輸出成功只代表軟體就緒，還沒有證明實體動作與停止效果。

## 5. 依順序驗收

| 順序 | 操作 | 通過判據 |
|---|---|---|
| A 連線 | 掃描 → 對照完整 MAC → 連線，保持練習模式 | 清單、標籤、畫面相同，能讀電量 |
| B 重連 | 斷開、關閉工具、重新打開；再測換 DHCP 地址 | 同一 MAC 可重新發現，不續跑舊程式 |
| C 占用 | 第二台電腦嘗試連同一隻狗 | 使用中被拒絕，原使用者釋放後才可接手 |
| D 姿態 | 老師示意後站立、停止、趴下 | 動作正常，每次目視確認停止 |
| E 短動作 | 低速前進 0.5 秒、左右各 15 度 | 記實際延遲、距離與方向，動作後停止 |
| F 停止 | 運動中按停止；按現場方案測斷網、關閉工具與故障 | 實體停止可確認，記延遲 / 距離，必要時用硬體停止 |
| G 影像 | RTSP、模型、即時卡片確認與超時 | 有持續新畫面；確認和超時兩種行為正確 |
| H 增載 | 逐步加電腦與狗，記錄同時相機數 | 在目標組數下連線、影像和停止流程仍可用 |

先用已測過的短程式。以下測試在學生工坊 Python 視圖執行，先用練習模式核對，再取得老師示意切到實機：

```python
dog.stand()
dog.forward(seconds=0.5)
dog.stop()
dog.lie()
```

單次平移最多 3 秒、速度最高 0.2 m/s；轉向最多 45 度，程序最多 60 秒；電量低於 30% 不開始。轉角是時間估算，仍需量測。軟體「停止指令已接受」不是物理已停的證明；停止未確認時通知負責人、保持距離，按已驗證的現場硬體停止方案處理。

## 6. 記錄結果與回到程式修改

```powershell
New-Item -ItemType Directory -Path field-results -Force
Copy-Item docs/實機測試記錄範本.md field-results/第一次實機測試.md
git rev-parse HEAD
```

記錄 commit、Release、機型 / 韌體 / MAC、時間、觀察者、預期、實際及下一次只改哪一項。列印資料中也有現場驗收與試教表。`field-results/`、`local/`、學生作品與原始日誌均被 Git 忽略。

問題若需要改程式，先最小化重現、去除公司資訊與控制憑證，再按 [開發與重建](../d1-classroom/README.md) 修改。軟體修正可 commit；不要把真機的 robot.json、備份或 session 憑證加入倉庫。

下一次到公司先 `git pull --ff-only`。本版下載清單固定指向 v2.0.0；未來新 Release 需先更新倉庫內的版本清單，再重新取得成品，不能只更新 EXE。


## 排錯速查與回復

| 現象 | 先檢查 | 下一步 |
|---|---|---|
| gh 找不到倉庫或 Release | `gh auth status`、帳戶是否能看私人倉庫 | 登入相同帳戶；不要把 token 貼到文件 |
| SHA-256 不符 | 是否沿用舊下載、檔案被截斷 | 把錯誤 ZIP 移出 downloads，重下同一 Release |
| EXE / 教程缺檔 | 是否只複製 EXE 或解壓不完整 | 保留作品後，用 `-Replace` 重新取回整套 |
| 掃不到 | 同 IPv4 網段、AP 隔離、VPN、防火牆 | 狗端 `systemctl is-active d1-classroom`，再查服務日誌 |
| 準備中 / 初始化失敗 | CPython 3.10、架構、原廠服務、SDK 機內地址 | 查 journalctl，按原廠指南核對後重跑相同安裝命令 |
| MAC 不一致 | Wi-Fi / 有線是否看成不同網卡 | 按安裝輸出的 Wi-Fi MAC 更新標籤，重新掃描 |
| 連線中斷 | 網路穩定性、狗端 SDK / 服務日誌 | 確認機身停止，修復後重新連線，不續跑 |
| 相機黑畫面 | 同網可達、TCP 8554、原廠 RTSP | 保持靜止，核對 `rtsp://當次IP:8554/test`；先用電腦相機做分類練習 |

要停用橋接時，先完成停止並目視確認機身靜止、關閉 Windows 控制端，再在狗上執行 `sudo systemctl disable --now d1-classroom`。重新啟用用 `sudo systemctl enable --now d1-classroom`。升級或重裝同樣先確保靜止，再執行已核對的初始化包，不刪原廠運動服務、不更換作業系統。
